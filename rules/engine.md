# rules/engine.md — 执行引擎编码规范（apps/engine）

> 由 AGENTS.md §2 引用。架构见 `docs/architecture/engine-execution-architecture.md`（角色/数据流/状态机）；本文件是编码级细则。

## 1. 边界与依赖

1. engine **禁止**依赖 `apps/web`、`packages/db`（无数据库访问）；与 web 只通过 BullMQ 队列 + HTTP 回调交互。
2. 所有跨进程契约（任务指令、事件流帧、控制信号、心跳）的 zod schema 定义在 `packages/shared/execution/`，双方从该处导入——**禁止 engine/web 各自手写**。
3. engine 内部分层固定：`runner/`（队列消费、并发槽、心跳、状态机）→ `kernel/`（步骤树解释器、变量上下文、断言/提取管线，纯函数）→ `samplers/`（协议采样器实现）。

## 2. 任务生命周期

1. 状态机只能前进：`pending → dispatched → running → success | failed | stopped | dead`；任何状态流转必须持久化（回调 + Redis 双写），终态写入必须幂等（重复回调不得产生第二个终态）。
2. 回调失败按指数退避重试（上限 5 次），超过转 `dead` 并落死信队列；心跳丢失 3 拍标记节点不可调度，运行中任务由 web 侧超时回收。
3. 取消必须传播：BullMQ 控制信号 → AbortController → 取消在途采样/脚本/等待；取消后的日志帧照常入流（终态 `stopped`）。

## 3. 事件流

1. 每个步骤必须成对产出 `step-start` / `step-final`；`seq` 任务内单调递增，禁止回退与空洞。
2. 事件写入 Redis Stream 用 pipeline 批量（≥10 条或 500ms 触发刷写）；进程崩溃重启后从已确认 seq 续传，禁止重发已确认帧。
3. 事件 `payload` 只放结构化数据（请求快照、断言明细、变量结果）；大响应体截断存储（上限 256KB，超出标记 `truncated: true` 并存 MinIO 引用）。
4. 日志与报告同源：禁止 engine 单独为报告再产一份「结果文件」。

## 4. kernel（解释器）实现约束

1. **纯函数优先**：步骤树解释、变量渲染、断言求值、提取匹配必须是可单测的纯函数（输入步骤+上下文 → 输出事件），IO（发请求/读文件/SQL）只存在于 sampler 与脚本沙箱。
2. 变量作用域链实现顺序固定：临时参数 > 场景参数 > 环境变量/全局参数；同名覆盖必须可解释（实现与 glossary 术语一致）。
3. 函数语法解析：`@mock` 函数与 `${__fn}` JMeter 兼容函数在**渲染管线同一阶段**解析；未识别函数必须报错（禁止静默原样输出导致隐性 bug）。
4. 循环控制器必须带最大迭代数硬上限（防 while 死循环，对齐基线超时保护）；超时时间作用于整步骤树时也要有任务级总超时。

## 5. 采样器（samplers/）

1. 采样器实现 `SamplerPlugin` SPI（协议插件同接口）；核心库只内置 HttpSampler（undici）。
2. 每个采样器必须归一化三类失败并给分类码：网络错误（DNS/连接/超时）、断言失败、脚本/配置错误——报告与误报规则按分类码工作。
3. 默认连接/响应超时 60s，可被请求级/环境级覆盖；跟随重定向默认开启且记录中间跳转（对齐基线）。
4. 请求重放（失败重跑/本地执行）必须可从任务定义完整重建请求——采样器内禁止隐藏状态（如复用连接级 cookie，除非 Cookie 策略显式开启）。

## 6. 脚本沙箱

1. JavaScript（quickjs-emscripten）：无 IO、CPU/内存/时长限额；暴露上下文对象白名单（vars/assert/log/prev/props），禁止透传宿主对象。
2. Python（可选，P2）：子进程 + 资源限额 + 超时强杀；stdio 经事件流透传。
3. 沙箱超时/超限属于「脚本错误」分类码，不得让引擎进程崩溃——任何脚本异常必须收敛为步骤失败事件。

## 7. 本地模式与资源池

1. `engine --local`：同一内核，输出从「队列+回调」切「本地执行 + 回环上报」；上报带个人 APIKEY，断线时本地缓冲（磁盘队列）重连重发，顺序保证。
2. 节点注册/心跳信息（并发槽容量、版本、协议能力）经 `packages/shared` 契约上报；版本不匹配的任务不下发。
3. 并发槽：全局 p-limit + 每任务并发上限双层；槽位占用可观测（metrics 见 rules/observability.md）。

## 8. 引擎测试要求

1. kernel 纯函数 100% 分支单测（解释器/渲染/断言/提取是质量核心）；采样器用录制的响应 fixture 做单测，真实网络只出现在集成测试。
2. 集成测试：任务全生命周期（含取消/崩溃恢复/回调重试/事件续传）各至少一条；崩溃恢复测试必须真的 kill 进程验证。
