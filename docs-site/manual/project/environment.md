# 环境管理

环境定义了一组执行上下文：变量、HTTP 域名、HOST、数据源与全局前后置处理。接口调试、接口用例与场景执行时引用环境，实现「一套定义、多环境切换」。

<img src="_media/shots/environments.png" alt="环境管理">

## 概念

- **环境**：项目级资源，由五个配置区组成，编辑器以五个 Tab 呈现。
- **环境组**：将多个环境编组管理（S5 引入），配合全局参数使用。
- **全局参数**：项目级公共变量，作用域低于环境变量（见下方作用域链）。
- **执行快照**：执行时由 web 端构建环境快照注入执行引擎，引擎本身不依赖数据库，保证执行一致性。

路径：`/settings/environments`（项目 › 设置 › 环境管理），左侧为环境列表，右侧为五区编辑器。

## 操作流程

1. 进入 项目 › 设置 › 环境管理，点击「新建环境」；
2. 在编辑器中按需配置五个区（变量 / 域名(HTTP) / HOST / 数据源 / 全局前后置与断言）；
3. 保存后，在接口调试、接口用例、场景执行处选择该环境即可生效。

## 编辑器五个配置区

| # | 区域           | 内容                                                                                                     |
| - | -------------- | -------------------------------------------------------------------------------------------------------- |
| ① | 变量            | 键值对列表；请求中通过 `${var}` 渲染消费                                                                  |
| ② | 域名(HTTP)      | protocol / hostname / port / pathPrefix，可配置多条，按模块或路径前缀条件路由                              |
| ③ | HOST            | 域名绑定（类似本地 hosts），将指定域名解析到指定地址                                                       |
| ④ | 数据源          | 数据库连接配置（供 SQL 处理器使用）                                                                       |
| ⑤ | 全局前后置/断言/提取 | 环境级全局处理器，作用于引用该环境的每次执行（含公共脚本引用 ScriptRefPanel）                          |

### 变量与域名如何生效

- **变量渲染**：请求的 URL、请求头、请求体等位置写 `${var}`，执行时按作用域链解析。

  ```text
  作用域链：临时变量（API-004 提取） > 环境变量 > 项目全局参数
  ```

- **URL 拼接**：请求中写相对路径（如 `/api/users`）时，由环境的 HTTP 域名（协议+主机+端口+路径前缀）拼接为完整地址；条件路由可让不同模块或路径前缀命中不同域名。
- **公共脚本引用**：前后置 script 处理器可通过 `scriptRef` 引用项目公共脚本（构建期展开），见 [公共脚本](manual/project/script.md)。

## 字段说明（域名(HTTP)）

| 字段       | 说明                                   |
| ---------- | -------------------------------------- |
| protocol   | http / https                           |
| hostname   | 主机名或 IP                            |
| port       | 端口，可留空用协议默认端口             |
| pathPrefix | 路径前缀，拼接在相对路径之前           |
| 条件路由   | 按模块或路径前缀匹配，决定哪条域名生效 |

## 使用示例

假设环境配置：变量 `host_token=abc123`，域名 `https://api.example.com:8443/v2`：

```text
请求 URL（相对路径）：/users/${user_id}
执行时实际请求：     https://api.example.com:8443/v2/users/1001
请求头：             Authorization: Bearer ${host_token}
                     → 渲染为 Authorization: Bearer abc123
```

多环境切换时，只需在执行处更换环境（如「测试环境 → 预发环境」），同一套用例/场景无需修改任何定义。

## 环境在各类执行中的入口

| 执行场景   | 环境使用方式                             |
| ---------- | ---------------------------------------- |
| 接口调试   | 调试页选择环境，即时生效                 |
| 接口用例   | 用例执行时选择环境                       |
| 场景执行   | 手动执行选择环境；定时任务绑定环境       |
| 测试计划   | 计划内接口/场景执行沿用所选环境          |

## 边界与注意事项

- 环境是项目级资源，跨项目不可见；同项目内接口调试/用例/场景共享同一套环境。
- 执行时环境以快照注入引擎：执行中修改环境不影响已开始的任务。
- 数据源区的 SQL 处理器依赖数据源配置，当前编辑暂未开放（可经导入携带）；SQL 处理器执行受引擎静态安全门禁限制，见 [公共脚本](manual/project/script.md) 边界说明。
- 变量名避免与临时提取变量冲突——临时变量优先级最高，会覆盖同名环境变量。
