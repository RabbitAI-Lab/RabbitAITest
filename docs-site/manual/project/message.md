# 消息管理

消息管理把项目事件（缺陷、评审、计划执行、场景执行、定时任务等）推送到指定渠道与人。页面分三个 Tab：通知机器人、事件配置、消息模板（企业版）。配套的站内消息中心提供收件查看。

## 概念

路径：`/settings/messages`（项目 › 设置 › 消息管理）。

- **通知机器人**：一条机器人 = 一个投递渠道端点（站内信、邮件或三方群机器人 Webhook）。
- **事件配置**：决定「哪个事件 → 通过哪些机器人 → 发给哪些人」。
- **接收人合并规则**：实际接收人 = 事件配置接收人 ∪ @提及人 ∪ 关注者 − 操作人（同人去重，操作人自己不收自己触发的事件）。

## Tab 1：通知机器人

支持 5 种渠道，每个项目最多创建 10 个机器人：

| 渠道     | 类型     | 必填配置                     |
| -------- | -------- | ---------------------------- |
| 站内信   | 平台内置 | 无（消息进入站内消息中心）   |
| 邮件     | 平台内置 | 无（使用系统 SMTP 参数发信） |
| 企业微信 | 机器人   | Webhook URL                  |
| 钉钉     | 机器人   | Webhook URL                  |
| 飞书     | 机器人   | Webhook URL                  |

!> 机器人渠道（企微/钉钉/飞书）必须填写 Webhook URL，否则无法保存。邮件渠道依赖管理员在系统参数中配置 SMTP（见 [参数设置](manual/system/params.md)），未配置时邮件投递失败。

## Tab 2：事件配置

覆盖 11 个事件，按五大类组织：

| 分类     | 事件 key                | 说明                         |
| -------- | ----------------------- | ---------------------------- |
| 缺陷管理 | BUG_CREATED             | 缺陷创建                     |
| 缺陷管理 | BUG_UPDATED             | 缺陷更新（含处理人转派）     |
| 缺陷管理 | BUG_DELETED             | 缺陷删除                     |
| 缺陷管理 | BUG_COMMENT             | 缺陷评论（@提及人必收）      |
| 缺陷管理 | BUG_TRANSITION          | 缺陷流转（关注者必收站内信） |
| 用例评审 | REVIEW_COMMENT          | 评审评论（@提及人必收）      |
| 用例评审 | CASE_COMMENT            | 用例评论（@提及人必收）      |
| 测试计划 | PLAN_EXEC_COMPLETED     | 计划执行完成                 |
| 接口测试 | SCENARIO_EXEC_COMPLETED | 场景执行完成（手动/定时）    |
| 定时任务 | SCHEDULE_ENABLED        | 定时任务启用                 |
| 定时任务 | SCHEDULE_DISABLED       | 定时任务停用                 |

每个事件可配置：启用开关、生效机器人（单事件至多 10 个）、配置接收人（至多 50 人）。**事件总闸**：事件开关关闭时该事件不发送任何通知（@提及与关注也不例外）。

事件配置字段：

| 字段            | 约束       | 说明                                     |
| --------------- | ---------- | ---------------------------------------- |
| enabled         | —          | 事件总闸，关闭则该事件全渠道静默         |
| robotIds        | 至多 10 个 | 该事件生效的通知机器人                   |
| receiverUserIds | 至多 50 人 | 配置接收人（与 @提及人、关注者合并去重） |

## Tab 3：消息模板（企业版）

> 此能力由企业版 License 的 MSG_TEMPLATE 特性门控，社区版不开放，见 [认证与授权（企业版）](manual/system/enterprise.md)。

- 11 个事件均支持自定义消息模板；
- 模板中写 `${var}` 占位符，每个事件提供变量目录（公共变量：项目名、操作人等 + 对象变量）；
- 支持实时预览与「恢复默认」。

## 站内消息中心

两个入口：

| 入口                      | 能力                                                                    |
| ------------------------- | ----------------------------------------------------------------------- |
| 顶栏通知铃铛              | 未读徽标（30 秒轮询未读数）；点开显示最近 10 条；打开面板即标记全部已读 |
| `/personal/notifications` | 完整列表：仅近 90 天、仅未读筛选、单条已读、全部已读                    |

## 关注（Follow）

关注是通知的另一来源：用例、计划、评审、接口用例、场景、缺陷均提供关注入口，关注后对象变更（如缺陷流转）会触发通知。配合事件配置，实现「关键对象变动我不漏」。

## 边界与注意事项

- @提及人与关注者的通知不占用「配置接收人」名额，但受事件总闸约束。
- 站内信保留近 90 天，超期自动不再展示。
- 三方机器人 Webhook 属敏感配置，泄露可能导致消息外发，请妥善管理。
