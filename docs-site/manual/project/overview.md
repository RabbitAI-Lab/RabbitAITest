# 项目与模板

RabbitAITest 以「组织 → 项目 → 模块」三级结构组织测试资产。本页介绍项目管理全流程：项目基本信息与模块开关、组织/项目两级成员与用户组、以及「字段定义 × 模板」两层结构的模板管理。

> 所需权限：项目级操作要求 PROJECT_ADMIN 相关权限点；组织级管理要求 ORG_ADMIN 相关权限点；多组织管理（/system/orgs）为企业版 MULTI_ORG 特性。

## 概念：组织、项目与模块

- **组织**：资源与成员的顶层容器。组织级页面包括项目管理（`/org/projects`）、成员管理（`/org/members`）、部门管理（`/org/departments`）、用户组（`/org/groups`）、模板管理（`/org/templates`）。
- **项目**：测试资产的主体（用例、接口、场景、计划、缺陷、环境、文件、脚本均挂在项目下）。
- **模块**：项目内的树形分组，按场景区分：功能用例树、接口用例树、场景树、缺陷树、文件树等。每个项目初始化三个默认模块：**未规划用例 / 未规划接口 / 未规划场景**。

## 项目管理（组织级）

路径：`/org/projects`。组织管理员在此新建、编辑项目，维护项目列表。

新建项目流程：

1. 进入 组织 › 项目管理，点击「新建项目」；
2. 填写项目名称、描述，勾选需要开启的模块开关；
3. 保存后项目出现在顶栏项目切换器中，进入项目即可开始配置成员、模板与环境。

## 项目基本信息

路径：`/settings/info`（项目 › 设置 › 基本信息）。

| 字段     | 说明                                                                                                                             |
| -------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 项目名称 | 必填，显示于项目切换器                                                                                                           |
| 描述     | 选填                                                                                                                             |
| 模块开关 | case 测试用例 / plan 测试计划 / bug 缺陷管理 / api 接口测试（默认开启）；load 性能测试 / uit UI 测试（默认关闭，企业版方向占位） |
| 项目状态 | 项目生命周期状态                                                                                                                 |

模块开关关闭后，对应左侧导航入口消失（双门控规则见 [通用功能](manual/common/overview.md)），但已存在的数据保留。

## 成员与用户组

成员管理分两级，均为「成员列表 + 用户组」结构：

| 层级   | 页面                                    | 说明                                               |
| ------ | --------------------------------------- | -------------------------------------------------- |
| 组织级 | `/org/members`、`/org/groups`           | 管理组织内成员与组织级用户组，成员可批量加入项目组 |
| 项目级 | `/settings/members`、`/settings/groups` | 管理当前项目成员与项目级用户组，控制项目内权限     |

操作流程（项目级）：

1. 进入 项目 › 设置 › 成员管理，点击「添加成员」，从组织成员中选择并指定项目用户组；
2. 在 项目 › 设置 › 用户组 中维护用户组与权限（各组权限并集 − deny 交集，规则见通用功能页）；
3. 成员被移出项目组后立即失去对应项目权限。

?> 预置六组（isSystem 只读）：系统管理员/系统成员/组织管理员/组织成员/项目管理员/项目成员。项目成员（PROJECT_MEMBER）已含用例读写、评审、计划读改、缺陷读写、接口/环境/文件/脚本创建等日常权限。

## 模板管理

模板体系为两层结构：**字段定义 × 模板**。

| 页面                  | 层级 | 内容                                                                |
| --------------------- | ---- | ------------------------------------------------------------------- |
| `/org/templates`      | 组织 | 字段定义 Tab + 模板 Tab；项目启用项目模板前，全组织项目共用组织模板 |
| `/settings/templates` | 项目 | 项目级模板（用例模板、缺陷模板等）与工作流，工作流按生效模板编辑    |

- **字段定义**：定义对象的字段集（名称、类型、选项、是否必填等），是模板的底座。
- **模板**：在字段定义之上组合出可复用的模板（如不同类型用例/缺陷模板），项目内创建对象时选用。

操作流程：

1. 组织管理员在 组织 › 模板管理 › 字段 Tab 维护字段定义；
2. 在 模板 Tab 创建组织级模板供全组织项目使用；
3. 项目需要差异化时，在 项目 › 设置 › 模板管理 启用项目级模板与工作流。

## 边界与注意事项

- 删除/停用模块开关不影响存量数据，但会隐藏导航入口并拦截新操作。
- 组织模板与项目模板的生效关系：项目启用项目模板前共用组织模板；启用后以项目模板为准。
- 部门管理（`/org/departments`，左树右表）用于组织内人员归属管理，属企业版 USER_SCALE 特性配套，见 [认证与授权（企业版）](manual/system/enterprise.md)。
- 多组织（一个部署多个组织）为 License 门控的企业版能力，社区版单组织运行。
