# 文件管理

文件管理是项目的公共文件库：上传并维护项目级文件（测试数据、驱动 JAR 等），供接口执行引用；同时支持绑定 Git 仓库作为文件源，从仓库分支同步文件。

> 所需权限：文件列表查看要求项目文件读权限；上传/重命名/移动/JAR 开关要求 PROJECT_FILE:UPDATE；删除要求 PROJECT_FILE:DELETE。

## 概念

路径：`/files`（项目 › 文件管理）。页面为「左侧文件场景模块树 + 上传区 + 筛选 + 文件列表」布局，并提供「回收站」视图与「Git 仓库」配置入口。

文件按来源分两类：

| 来源   | 说明                                                         |
| ------ | ------------------------------------------------------------ |
| 本地   | 通过上传区手工上传的文件                                      |
| Git 仓库 | 从绑定的 Git 仓库（指定分支与路径）同步的文件，来源列显示仓库平台标签 |

## 操作流程

### 上传与管理本地文件

1. 进入 项目 › 文件管理，在左侧模块树选中目标模块（可勾选「包含子模块」）；
2. 点击上传区选择文件（可按关键字筛选已有文件）；
3. 在列表中执行管理操作：重命名、移动到其他模块、下载、删除。

### JAR 开关

对于 JAR 文件，列表提供独立开关：

- 开启后项目内前后置脚本可引用该 JAR；
- 默认禁用；开关状态对全项目生效。

### 回收站

删除的文件进入回收站（软删除）：

- **恢复**：将文件恢复到原模块；
- **彻底删除**：从回收站永久移除；
- **重新拉取**：Git 仓库来源的文件可从仓库重新拉取。

回收站视图在列表中额外展示「删除时间」列，便于按时间定位误删文件。

### Git 仓库文件源（FILE-001）

1. 点击「Git 仓库」打开仓库配置弹窗，登记仓库地址、分支与路径；
2. 保存后平台从仓库同步文件到文件库，来源列显示仓库平台标签；
3. 仓库删除后，其来源文件标记「已删仓库」。

适用场景：测试数据、断言样本等由研发仓库统一维护的文件，仓库侧提交后同步即可用，免去手工上传与版本不一致问题。

## 列表字段

| 列     | 说明                                                         |
| ------ | ------------------------------------------------------------ |
| 名称   | 文件名；Git 来源文件悬停显示 分支 · 仓库路径                  |
| 来源   | 本地 / 仓库平台标签 / 已删仓库                                |
| 大小   | 文件大小                                                      |
| 模块   | 所属文件场景模块                                              |
| JAR    | JAR 文件显示启用开关（Tooltip：JAR 启用后项目内前后置脚本可引用，默认禁用） |
| 操作   | 下载 / 重命名 / 移动 / 删除（回收站视图为恢复 / 彻底删除 / 重新拉取） |

## 筛选与定位

- **模块树**：左侧按文件场景模块过滤，可切换「包含子模块」；
- **关键字**：按文件名关键字搜索；
- **分页**：列表分页展示（每页 20 条）。

## 边界与注意事项

- 单文件大小上限由系统参数控制（系统 › 参数设置 › file 组，默认 50MB），见 [参数设置](manual/system/params.md)。
- 删除为软删除：文件进入回收站后，**执行中引用该文件的任务将以 CONFIG_ERROR 失败**，请先确认无引用再删除。
- Git 仓库文件在仓库侧变更后需重新拉取才会更新本地副本。
- form 请求体的文件参数可引用文件库中文件的 fileId，实现上传文件随请求发送（见 [接口调试](manual/api/debug.md)）。
