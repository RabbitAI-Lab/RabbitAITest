# 资源池

资源池是执行任务的算力容器：接口用例、场景、计划等任务入队到资源池，由绑定该池的执行引擎（engine 节点）消费执行。管理员在资源池页面维护池与并发配置。

> 所需权限：SYSTEM_POOL:READ / SYSTEM_POOL:UPDATE（多资源池增删改随企业版 MULTI_POOL 特性授权）

## 概念

路径：`/system/pools`（系统 › 资源池）。

系统初始化后自带一个**默认资源池**：

| 属性           | 值                                   |
| -------------- | ------------------------------------ |
| id             | `00000000-0000-0000-0000-000000000001` |
| 名称           | 默认资源池                           |
| 类型           | NODE                                 |
| isDefault      | 是                                   |
| maxConcurrency | 4（初始值，可由心跳动态下发调整）    |

执行链路：任务入队到池对应的 Redis 队列（`exec-pool-{poolId}`，默认池恒为 `exec` 队列）→ 绑定该池的引擎节点按并发槽领取执行。引擎进程通过环境变量 `POOL_ID` 绑定所属池；未设置时归属默认池，单引擎部署零感知。

## 池类型

| 类型 | 说明                                                                 |
| ---- | -------------------------------------------------------------------- |
| NODE | Node.js 引擎节点池（当前默认与主要形态）                              |
| K8S  | Kubernetes 池：配置 apiServer / namespace / token / image 四项，并提供连通性试连。**社区版为占位口径（EXEC-004）：试连验证配置但配置未落库，不提供实际 K8S 执行能力** |

## 操作流程

1. 进入 系统 › 资源池查看池列表（名称、类型、并发、节点状态）；
2. 编辑池的并发上限：修改后经引擎心跳动态下发生效；
3. （企业版）新建多个池、启停池、配置池应用组织。

节点在线状态由心跳判定；心跳同时做引擎版本协商，版本与平台契约不一致的节点标记 UNMATCHED——仅供展示，平台不会向其下发新类型任务。

节点状态说明：

| 状态      | 含义                                       |
| --------- | ------------------------------------------ |
| ONLINE    | 心跳正常，可调度                           |
| OFFLINE   | 心跳超 3 拍未上报，不可调度                |
| UNMATCHED | 引擎版本与平台契约不一致，不下发新类型任务 |

?> 新建池后，以 `POOL_ID={池id}` 环境变量启动执行引擎，节点即自动注册到该池；修改并发上限后约一个心跳周期生效（节点表槽位随之变化）。

引擎绑定示例（企业版多池场景）：

```bash
# 将一个 engine 节点绑定到指定资源池（未设置则归属默认池）
POOL_ID=<池id> pnpm --filter engine dev
```

## 多资源池（企业版）

> 多资源池由企业版 License 的 MULTI_POOL 特性门控，社区版仅默认单池，见[认证与授权（企业版）](manual/system/enterprise.md)。

| 能力             | 说明                                                             |
| ---------------- | ---------------------------------------------------------------- |
| 池 CRUD          | 新建/编辑/删除多个资源池                                          |
| 组织范围 orgScope | 池应用组织：ALL（全部组织）或指定组织                             |
| 池启停           | 停用后不再接收新任务                                              |
| 默认池保护       | 默认资源池不可删除、不可禁用                                      |
| 执行入口池校验   | 发起执行时校验所选池可用性，不满足即拒绝                          |
| 队列隔离         | 每池独立队列 `exec-pool-{poolId}`，任务按池路由                  |

## 边界与注意事项

- 并发上限是池级总并发（跨节点共享），由心跳动态下发，修改无需重启引擎。
- 默认资源池受保护：任何时候可依赖其承接无明确池指向的任务。
- K8S 类型在社区版仅用于查看与试连验证，配置不落库，勿在生产依赖其执行。
- 池不可用或并发占满时，任务停留在 PENDING（见[任务中心](manual/project/task-center.md)）。
- 节点 OFFLINE 超过 3 个心跳拍即判定，恢复心跳后自动回到 ONLINE。
