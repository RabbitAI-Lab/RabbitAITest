# 插件管理

插件管理负责三方插件的接入与生命周期：上传插件包、预览清单、登记/启用/停用/删除，并查看插件运行状态。插件体系支持协议扩展、三方平台对接与驱动三类扩展点。

> 所需权限：SYSTEM_PLUGIN:READ / SYSTEM_PLUGIN:UPDATE

## 概念

路径：`/system/plugins`（系统 › 插件管理）。插件由 plugin-runner（worker_threads）隔离加载执行，与主进程故障隔离。

插件类型（kind）：

| 类型     | 用途                                 | 仓库自带示例                                  |
| -------- | ------------------------------------ | --------------------------------------------- |
| protocol | 协议扩展，为请求编辑器提供新协议采样 | tcp-conn、websocket、mqtt                     |
| platform | 三方平台对接（缺陷同步等）           | jira-platform、zentao-platform、tapd-platform |
| driver   | 驱动类扩展                           | —                                             |

## 生命周期

操作流程：

1. **上传**：上传插件 tarball；
2. **清单预览**：解析 package.json 中的 `rabbitPlugin` 清单字段并展示，人工确认；
3. **登记**：确认后登记入库，默认**停用**状态；
4. **启用**：启用后 plugin-runner 热加载，立即可用；
5. **停用**：停用后不可调用，**配置保留**，可再次启用；
6. **删除**：彻底移除插件登记。

## 插件清单（rabbitPlugin）

清单声明于插件包 `package.json` 的 `rabbitPlugin` 字段：

| 字段       | 说明                                  |
| ---------- | ------------------------------------- |
| name       | 插件名                                |
| kind       | protocol / platform / driver          |
| version    | 插件版本                              |
| spiVersion | 声明兼容的 SPI 版本（当前宿主为 1.0） |
| entry      | 入口文件                              |

!> 插件 spiVersion 必须与宿主当前 SPI 版本（1.0）匹配，不兼容将被拒绝加载（错误码 70003）。

## 列表字段

| 列       | 说明                                        |
| -------- | ------------------------------------------- |
| 名称     | 插件名；处于 ERROR 态时展示 worker 异常信息 |
| 类型     | protocol / platform / driver                |
| 版本     | 插件版本                                    |
| SPI 版本 | 清单声明的 SPI 版本                         |
| 组织范围 | orgScope：ALL（全部组织）或指定组织         |

## 隔离与稳定性机制

| 机制         | 值/规则                                           |
| ------------ | ------------------------------------------------- |
| 线程隔离     | 每插件一个 worker_threads 线程                    |
| 崩溃退避重启 | 1s / 4s / 16s 递增退避                            |
| 连续失败标记 | 连续 3 次启动失败标记 ERROR（列表名称处显示异常） |
| 调用超时     | 30 秒                                             |
| 内置插件     | 随进程注册（如 platform-echo），无需上传          |

## 协议插件的使用

- 启用 protocol 插件后，其提供的协议出现在请求编辑器的**协议选择器**中（数据源为 `GET /api/v1/plugins/protocols`，普通项目成员可见）；
- 协议插件可提供会话级协议选项；
- 接口定义/用例**保存时做协议可用性校验**：引用了未启用/不存在的协议将被拒绝（业务码 40511）。

## 边界与注意事项

- 平台对接（Jira/禅道/TAPD）依赖对应 platform 插件处于启用状态，否则缺陷同步中断，见[服务集成与同步](manual/project/integration.md)。
- 停用插件仅中断调用，登记与配置保留；删除不可恢复，需重新上传。
- ERROR 态插件不参与调用，请根据列表展示的异常信息排查（如入口错误、SPI 不兼容）后再启用。
