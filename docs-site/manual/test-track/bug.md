# 缺陷管理

RabbitAITest 内置本地缺陷管理，覆盖缺陷的提报、流转、评论协作、关联用例与回收站，与测试计划执行结果联动，形成「执行失败 → 提缺陷 → 跟踪闭环」的完整链路。

> 所需权限：PROJECT_BUG:READ（查看）/ PROJECT_BUG:CREATE（新建）/ PROJECT_BUG:UPDATE（编辑、流转、评论、关注）/ PROJECT_BUG:DELETE（删除、彻底删除）。

## 概念

### 缺陷状态与工作流

缺陷状态来自项目绑定的**缺陷模板工作流**，可按项目自定义状态序列。默认工作流为：

```text
待处理 → 处理中 → 已关闭
```

其中「待处理」为起始状态，「已关闭」为终态。流转只能沿工作流定义的迁移进行，每次流转需确认并可附流转意见（意见随流转自动写入评论）。

### 缺陷构成

| 组成        | 说明                                              |
| ----------- | ------------------------------------------------- |
| 标题 / 编号 | 缺陷标识，列表与详情展示                          |
| 标签        | 自由标签，最多 10 个                              |
| 处理人      | 当前负责修复的人，列表可按处理人筛选              |
| 严重程度    | 模板动态字段，预置选项：致命 / 严重 / 一般 / 轻微 |
| 动态字段    | 由组织级字段定义经项目模板绑定注入，随模板扩展    |
| 关联用例    | 缺陷与功能用例的关联关系                          |

## 操作流程

### 1. 新建缺陷

1. 进入「缺陷管理」，点击「新建缺陷」。
2. 按模板表单填写标题、处理人、严重程度及动态字段，保存后进入缺陷详情页。

?> 在测试计划执行失败时，也可从执行结果直接发起缺陷创建，自动带上用例与执行上下文。

### 2. 处理与流转

缺陷详情页顶部提供**状态徽标 + 流转按钮组**：

1. 点击目标状态（如「处理中」），弹出流转确认框。
2. 可填写流转意见（可选），确认后状态更新；流转记录自动写入评论。

### 3. 评论与协作

详情页页签包括 **详情 / 关联用例 / 评论 / 变更历史**：

- **评论**：支持多人评论讨论，评论中支持 **@提及** 项目成员，被提及者会收到提醒。
- **变更历史**：以流转记录为主线（取流转时自动写入的评论，按时间倒序），查看状态演进轨迹。
- **关注**：点击关注后，该缺陷的变更会向你提醒；可在工作台「我关注的」中跟踪。

### 4. 检索缺陷

列表页（左侧缺陷模块树 + 右侧列表）提供筛选：

| 筛选     | 说明                             |
| -------- | -------------------------------- |
| 关键字   | 标题 / 编号搜索                  |
| 状态     | 按工作流状态（来自项目模板定义） |
| 标签     | 逗号分隔多标签                   |
| 严重程度 | 致命 / 严重 / 一般 / 轻微        |
| 处理人   | 按成员过滤                       |

### 5. 回收站

删除的缺陷进入回收站，可单条或**批量恢复**；也可**批量彻底删除**。

!> 彻底删除不可恢复：关联用例、评论、变更历史、关注关系会一并清除。

## 边界与注意事项

!> 缺陷状态选项与流转规则由项目绑定的缺陷模板决定，不同项目可能不同；新建项目默认使用「待处理 → 处理中 → 已关闭」工作流。

!> 严重程度是模板动态字段：预置选项为致命 / 严重 / 一般 / 轻微，组织管理员可通过字段定义调整。

!> 本页为本地缺陷管理；如需对接第三方缺陷平台，请关注后续集成能力（当前社区版本地闭环）。
