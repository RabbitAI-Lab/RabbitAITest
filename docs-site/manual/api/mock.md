# Mock 服务

Mock 服务为被测系统提供可控的模拟响应：按「接口路径 + 匹配条件」组织规则，命中即返回预设响应，保存即热更新，适合依赖方未就绪、异常分支注入与前后端并行开发联调。

> 规则管理入口在[接口定义](manual/api/definition.md)详情页的 MOCK 页签；所需权限随 PROJECT_API:READ / CREATE / UPDATE / DELETE。

## 概念

### 架构特点

- Mock 服务是独立无状态应用：规则来自 Web 端保存时写入 Redis 的**项目全量快照**，Mock 服务不连数据库、直读快照，因此**保存即热更新**，无需重启，实例可横向扩容。
- 每条规则的响应可配置延迟 `delayMs`，用于模拟慢接口 / 超时场景。

### Mock URL

一个接口的 Mock 地址统一展示为：

```text
{MOCK_PUBLIC_URL}/mock/{projectNum}{path}
```

其中 `{MOCK_PUBLIC_URL}` 为部署时配置的 Mock 服务对外地址（开发环境默认为 `http://mock:{4000+槽位}` 形式），`{projectNum}` 为项目编号，`path` 为接口路径。在定义详情 MOCK 页签可一键复制完整地址。

### 命中语义

| 规则 | 语义 |
| ---- | ---- |
| 多规则匹配 | 按「**匹配条件最多者**」优先：命中条件数多的规则胜出 |
| 未命中 | 返回 HTTP 404，业务体 `code: 40401`（无匹配 Mock 规则） |
| 禁用规则 | 透明下线，不参与匹配 |

## 操作流程

### 1. 创建 Mock 规则

1. 打开接口定义详情页的 MOCK 页签。
2. 点击「新建规则」，配置：
   - **规则名称**：便于识别（如「狗查询」）；
   - **匹配条件**：基于该接口的方法与路径，追加请求参数 / 请求头 / 请求体等匹配项（条件越多，规则越具体）；
   - **响应**：状态码、响应头、响应体；
   - **延迟**：delayMs（模拟慢响应）。
3. 保存后规则立即生效（热更新），Mock URL 即可被调用。

### 2. 管理规则

MOCK 页签的规则表列出每条规则的**匹配摘要 / 响应摘要 / 延迟**，支持编辑、启用禁用与删除；删除或禁用后规则即时下线。

### 3. 规则调试

规则表提供**规则调试**能力：在页内直接发起一次模拟请求，立即看到命中结果——

- 命中：显示命中规则名与将返回的响应（含延迟）；
- 未命中：显示 404 与如下响应体：

```json
{
  "code": 40401,
  "message": "无匹配 Mock 规则"
}
```

?> 调试无需真实调用外部地址，适合在保存规则前验证匹配条件写得是否准确。

### 4. 在被测系统中使用

把被测系统（或接口调试请求）的目标地址指向 Mock URL 即可。多环境切换时只需更换 `{MOCK_PUBLIC_URL}` 前缀。

### 5. WebSocket 回显端点

Mock 服务内置 `/ws/echo` 回显端点（RFC6455）：收到什么就回什么，可作为 WebSocket 协议插件采样与联调的确定性目标。

## 边界与注意事项

!> 匹配条件数量决定优先级：两条规则都命中时，条件更多（更具体）的规则生效；条件数量相同时行为以保存顺序为准，建议为关键规则设计可区分的条件。

!> Mock 服务依赖 Redis：Redis 不可用时 Mock 不可用；但 Web 端功能不受影响。

!> Mock 响应不会经过断言 / 提取等执行引擎逻辑——它是独立 HTTP 服务；断言验证请在[接口调试](manual/api/debug.md)中把 URL 指向 Mock 地址进行。
