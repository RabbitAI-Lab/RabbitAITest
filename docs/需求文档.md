# RabbitAITest 需求文档

> 一站式开源测试工作台 · 测试管理 + 接口测试 + AI
> 对标基线：[MeterSphere v3.x 功能清单](../MeterSphere功能清单.md)（基于官方文档 + 代码库逆向调研，2026-09）

---

## 一、项目定位

RabbitAITest 是一套**复刻 MeterSphere v3.x 社区版功能面**的开源一站式测试工作台，围绕「测试管理 + 接口测试 + AI 辅助」三大能力域，为测试团队提供用例管理、用例评审、测试计划、缺陷管理、接口测试（调试/定义/Mock/场景自动化）、工作台协作与 AI 生成能力，并预留企业版扩展层（SSO、多组织、多资源池等）。

**版本分层交付**（对齐 MeterSphere 社区版/企业版双轨）：

| 层                    | 能力                                                 | 交付节奏                |
| --------------------- | ---------------------------------------------------- | ----------------------- |
| 标准版（社区版对等）  | 测试管理 + 接口测试 + 工作台 + 协作 + 集成 + AI      | 23 周内生产可用（v1.0） |
| 企业版（X-Pack 对等） | SSO、多组织、多资源池、自定义主题、消息模板、License | +4 周（v2.0）           |

**产品主线节奏**：**2 周跑通 POC、8 周测试域核心可用、23 周标准版生产可用、27 周企业版核心交付**。严格按 P0→P4 优先级推进，上游能力未稳定不开发下游功能。

### 1.1 复刻范围与差异化

| 维度                | 说明                                                                                                                                                                                                            |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 完整复刻            | 测试用例（列表/脑图/导入导出/评审）、测试计划（测试点/计划组/报告）、缺陷管理（本地+三方同步）、接口测试（调试/定义/CASE/Mock/场景/报告/误报）、项目管理（模板/文件/消息/脚本/环境）、系统设置、工作台、AI 生成 |
| 架构替换            | 执行引擎不用 JMeter，自研 Node.js 异步采样内核（详见 `architecture/engine-execution-architecture.md`）；保留 JMeter 场景格式导入兼容                                                                            |
| 明确不做（P4 远期） | UI 测试（Selenium）、性能测试（分布式压测）——MeterSphere v3 社区版同样没有，仅在企业版方向占位                                                                                                                  |
| 优先做（超越基线）  | AI 能力前移（MeterSphere 已有，本项目在标准版内交付）；执行日志实时流；OpenAPI 原生                                                                                                                             |

## 二、用户与核心场景

| 角色       | 核心场景                                                          |
| ---------- | ----------------------------------------------------------------- |
| 测试工程师 | 维护用例（表单/脑图）、执行测试计划、调试接口、编排场景、提交缺陷 |
| 测试主管   | 制定测试计划与测试点、跟踪报告与通过率、评审用例                  |
| 开发工程师 | 接口联调（调试+Mock）、处理缺陷（与 Jira/禅道同步）               |
| 项目管理员 | 项目配置、成员与权限、模板、环境、消息通知                        |
| 系统管理员 | 用户/组织/项目、系统参数、插件管理、资源池、日志                  |

端到端主场景（POC 验收主线）：

```
登录 → 创建项目 → 建功能用例 → 调试一个 HTTP 接口（服务端/本地执行）
→ 保存为接口用例 → 编排进场景 → 执行并查看报告 → 关联测试计划 → 计划报告
```

## 三、功能模块需求（九大模块）

模块编号（与规格文档前缀一致）：**INFRA / SYS / PROJ / CASE / PLAN / BUG / API / EXEC / RPT / DASH / MSG / FILE / PLUG / INTG / AI / ENTP / QA / TOOL / LOAD / UIT**。

### M1 系统与组织（SYS）

- 三级管理体系：系统 → 组织 → 项目；预置角色（系统/组织/项目管理员与成员）+ 三级自定义用户组（菜单权限点勾选）
- 用户：创建/邮箱邀请/Excel 导入、编辑/重置密码/禁用/删除、批量加组
- 系统参数：站点 URL、SMTP、文件大小、数据清理（日志/变更历史保留时长）
- 资源池：Node 型（社区版限 1 默认池）、K8S 型（企业版）
- 插件管理（协议/平台/驱动上传与启停）、任务中心（实时/定时，失败重跑）、三级操作日志、授权管理（企业版 License 入口）
- 个人中心：个人信息、密码、APIKEY（≤5）、本地执行配置（连通检测）、三方平台账号、AI 模型设置

### M2 项目管理（PROJ / FILE）

- 应用设置：测试计划（报告保留/链接有效期）、缺陷（三方同步增量/全量/频率）、用例（重新提审/关联需求）、接口（报告保留/资源池/误报规则）
- 模板管理：用例/缺陷模板、自定义字段（多类型）、缺陷工作流（状态+流转矩阵）、组织/项目两级模板
- 文件管理：模块树、上传（JAR/CSV/脚本，JAR 启用制）、Git 存储库（Gitea/GitHub/GitLab/Gitee 按分支+路径拉取）
- 公共脚本：项目级脚本库（参数定义+多语言+在线调试+前后置引用）
- 环境管理：环境变量、HTTP 多域名条件匹配、数据库数据源、HOST、全局前后置/断言、TCP 配置（插件）、环境导入导出、环境组与全局参数

### M3 测试用例（CASE）

- 功能用例：表单创建（步骤/前置/预期/附件/标签/等级）、9 Tab 详情（需求/缺陷/依赖/评审/计划/评论/变更历史）、关注/分享/复制、回收站、批量操作、自定义视图
- 脑图模式：列表/脑图双向同步、模块→用例→步骤层级、快捷键体系、批量操作
- 导入导出：Excel/Xmind（覆盖/跳过策略；导出字段与格式选项）
- 用例评审：单人多/评审模式、评审人指定、批量评审、重新提审、脑图评审、通过率
- 需求关联：Jira/TAPD/禅道需求（依赖集成模块）

### M4 测试计划（PLAN）

- 计划与计划组、更多设置（重复关联/自动更新状态/通过阈值）
- 测试规划：功能/接口/场景三类 + 测试点分层（继承配置）
- 执行配置：资源池、环境、串行/并行、失败停止
- 执行：列表模式（实际结果/步骤结果）、脑图模式（S/E/B 快捷键）、缺陷关联/新建（带出步骤）、实时通过率
- 定时任务、批量操作、归档；报告：自动生成、总结、测试点维度明细、分享、导出 PDF

### M5 缺陷管理（BUG）

- 本地缺陷：模板创建（自定义字段/工作流）、附件（50MB）、列表操作、回收站
- 详情：关联用例、评论（回复/编辑/删除）、变更历史、关注/分享
- 三方同步：Jira/禅道/TAPD 双向同步（手动+定时）、增量/全量策略、平台字段映射模板

### M6 接口测试（API / EXEC / RPT / PLUG）

- **接口调试**：HTTP 起步（协议插件扩展）、8 方法、cURL 导入、服务端/本地执行、响应四视图
- **接口定义**：API/CASE/MOCK 三页签、导入（Swagger3/Postman/Har/JMeter/Rabbit 格式）、Swagger 定时同步、API 分享（密码/有效期/可导出）、引用关系、变更历史、API-CASE 差异同步
- **接口用例**：手动+AI 生成、执行历史、批量操作
- **Mock 服务**：匹配规则（头/Query/REST/体→响应）、跟随 API、Mock 地址外调、Mock 调试
- **请求参数体系**：7 种请求体、前后置（脚本 JS(quickjs)/Python(可选) + SQL + 等待 + 全局开关 + 代码片段）、提取（正则/JSONPath/XPath × 匹配模式 × 环境/临时变量）、断言 6 种、认证（Basic/Digest/脚本取 Token）、超时与重定向
- **场景自动化**：五配置区（步骤/参数/前后置/断言/设置）、7 类步骤（引用/复制导入、自定义请求、循环×3、条件、仅一次、脚本、等待）、CSV/列表/常量参数化（优先级体系）、Cookie/失败策略、导入导出（保留引用）、定时任务、批量操作
- **执行引擎**：Node 资源池调度、并发槽、实时日志流、失败重跑、本地执行器、内置函数库（Mock 函数 50+ + JMeter 函数兼容子集）
- **报告**：场景/用例两类报告、步骤级请求-响应钻取、分享（有效期）、批量导出、误报规则
- **插件**：协议插件 SPI（TCP 等）、数据库驱动插件化

### M7 工作台（DASH）

- 首页看板：项目概览、时间筛选、卡片设置（不展示/半屏/全屏）
- 我的待办/我关注的/我创建的（七维度筛选）

### M8 消息协作（MSG）

- 通知渠道 5 种：站内信、邮件、企业微信/钉钉/飞书机器人（Webhook）
- 通知场景 5 大类（计划/缺陷/用例与评审/接口测试全对象/定时任务）× 接收人配置（同人去重）

### M9 AI 能力（AI）

- 模型接入：系统级+个人级，OpenAI 兼容协议（DeepSeek/智谱/OpenAI）
- 功能用例生成（单条/批量）、接口用例生成（API 信息/Swagger 批量）、AI 助手对话（会话管理）、提示词与用例模板自定义

### M10 企业版（ENTP，P3）

- 多组织、SSO（LDAP/CAS/OIDC/OAuth2/SAML + 企微/钉钉/飞书扫码）、自定义主题与品牌、自定义消息模板、多资源池与 Controller、License 体系、用户扩容与部门管理

## 四、非功能需求

| 维度   | 要求                                                                                                                                                    |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 性能   | 单节点 100 并发接口任务稳定执行；万级用例列表筛选 < 1s；报告页 < 2s                                                                                     |
| 可靠性 | 执行任务不因引擎重启丢失（队列持久化 + 状态机恢复）；失败一键重跑                                                                                       |
| 安全   | 认证（Session+Token+APIKEY）、三级权限隔离、操作审计、插件进程隔离（驱动/脚本不进主进程）                                                               |
| 可部署 | 默认 embedded-postgres 单机免外部数据库（`DATABASE_URL` 可外接 PostgreSQL）；一键启动全套服务；数据备份/恢复脚本；升级不停数据（Prisma migration 纪律） |
| 可扩展 | 插件三类 SPI；协议扩展不动核心；模板/字段全动态                                                                                                         |
| 兼容   | MeterSphere 用例 Excel/Xmind 模板兼容导入；JMeter jmx 场景导入；Swagger3/OpenAPI                                                                        |

## 五、优先级分级与范围边界

| 级别   | 定义                              | 覆盖内容                                                                                                                  |
| ------ | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| **P0** | POC 阻塞级（Sprint 0，第 1-2 周） | 底座、认证、组织项目初始化、用例 CRUD、HTTP 调试闭环、执行器内核 v0、最小报告                                             |
| **P1** | MVP 必备级（Sprint 1-2）          | 用户组、模板字段、用例完整管理、评审、本地缺陷、计划基础、接口定义/CASE/参数体系、环境管理、任务中心                      |
| **P2** | 标准版完整级（Sprint 2-8）        | 场景自动化、Mock、脑图、计划完整与报告导出、消息通知、公共脚本、文件与存储库、三方缺陷同步、插件体系、CI 集成、AI、稳定化 |
| **P3** | 企业版核心级（Sprint 9）          | 多组织、SSO/扫码、主题、消息模板、多资源池、License、用户扩容                                                             |
| **P4** | 远期增强级（Sprint 10+）          | 性能测试（LOAD）、UI 测试（UIT）、WebSocket/MQTT 等协议插件、IDEA/浏览器插件（TOOL）、报告高级分析                        |

**范围红线（任何迭代不接受范围蔓延）**：

1. P0-P2 不做任何 ENTP 功能（不做 SSO/多组织/多资源池）
2. 标准版不做 UI 测试与性能测试（MeterSphere v3 社区版同口径）
3. 执行引擎不自研性能压测内核（P4 再议）
4. 移动端不做

## 六、验收维度（Release Gate）

- **功能**：对照 [MeterSphere功能清单](../MeterSphere功能清单.md) 逐模块做功能覆盖度核对（v1.0 目标：清单中社区版功能覆盖率 100%）
- **主链路 E2E**：第二章端到端主场景自动化测试通过
- **质量**：单测覆盖核心域 ≥ 70%；主链路 Playwright E2E 全绿；无 P0/P1 缺陷
- **性能**：100 并发任务 + 万级用例基线达标（QA-001）
- **交付**：Docker Compose 一键部署 + 完整用户手册 + API 文档（OpenAPI 自动生成）
