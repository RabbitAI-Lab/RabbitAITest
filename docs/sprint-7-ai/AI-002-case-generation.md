## 1. 概述

### 1.1 功能定位

用例列表工具栏「AI 生成」入口 → 抽屉输入需求文本 + 选目标模块 + 选提示词模板（AI-005）→ 调模型生成结构化用例草稿（JSON 容错解析）→ 草稿卡片勾选 → **经 CASE-001 既有创建端点导入**（权限/模板字段校验不绕过），留痕 AiGenRecord。

## 2. 业务逻辑

- **Prompt 组装**（system 常量 + 用户消息=模板渲染）：
  - system 开头固定：`你是 RabbitAITest 的测试用例生成助手`（mock 供应商分支依赖此稳定开头）；
  - 输出约束：仅输出 JSON 数组 `[{name,prerequisite,steps:[{desc,expect}],level,tags}]`，1-10 条，中文，level ∈ critical/high/medium/low；
  - 用户消息=模板（AI-005 或内置默认）渲染 `{{requirement}}/{{module}}/{{design_method}}`。
- **解析**：`extractJsonArray(text)` 纯函数（shared）——剥 ```json 栅栏→定位首个 `[` 扫描括号平衡截取→JSON.parse→非数组/空 70502；条目级弱校验（steps 至少 1 条），坏条剔除返回 `skipped` 明细。
- **导入**：前端逐条 POST 用例创建端点（携带 moduleId/level/tags/前置/步骤）；失败聚合展示（错误 message 逐条）；完成后写 AiGenRecord（generated=解析成功数, imported=成功数）。
- **边界**：模型禁用/删除后生成→70404/70444；需求空→422；模块不存在→30414（CASE 域真实校验）。

## 3. UI/UX 设计（高保真 docs/design/AI-002-case-generation/）

- 用例列表工具栏「AI 生成」按钮（Robot 图标）→ 右侧抽屉 640px：
  - 表单区：需求 textarea（8 行，计数 8000 上限）、目标模块 TreeSelect（默认「未分组」）、提示词模板 Select（默认模板带 ★，含「内置默认」项）、模型 Select（启用模型，默认 ★）
  - 「生成」按钮（loading 态：骨架条 3 根动画）；结果区草稿卡片：checkbox（默认勾）+ name + level Tag + 步骤数 + 展开看步骤明细（desc/expect 表）
  - 底栏：「导入所选 (N)」→ 结果反馈（成功 N 条/失败明细列表）
- 空态/异常态：无可用模型（引导去系统管理配置链接）、解析失败（70502 重试按钮）、全部剔除（提示重写需求）。

## 4. 技术架构

- 数据模型：AiGenRecord（随 S7 建表）。
- 契约：`aiGenerateCasesSchema`（requirement 1-8000/moduleId/templateId?/modelId?/designMethod?）、`aiCaseDraftSchema`（弱校验）、响应 `{drafts:[...], skipped:[{index,reason}], genRecordId}`。
- 端点：`POST /api/v1/projects/{pid}/ai/generate/cases`（PROJECT_AI:READ；**生成不落库用例**，导入走 CASE-001 既有端点）。
- 服务：`apps/web/src/server/domains/ai/generate.service.ts`（组装/调用/解析/留痕）；`extractJsonArray`+`CASE_GEN_SYSTEM_PROMPT`+内置默认模板放 shared（单测主力，纯函数）。
- 错误码：`AI_RESPONSE_UNPARSEABLE 70502`（422）、复用 AI-001 的 70404/70444/70501。
- 前端：`AiCaseGenerateDrawer.tsx`（cases 页挂载）；导入复用 api-client 既有 createCase。
