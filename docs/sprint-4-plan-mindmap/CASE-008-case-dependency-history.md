## 2. 业务逻辑

- **环检测**：新增边 (pre→post) 前沿 post 的后置闭包（BFS）检查是否可达 pre——可达则成环 422 `DEPENDENCY_CYCLE 50016`；同时禁止自引用（422 50017 SELF_DEPENDENCY）。闭包查询深度上限 100 防御。
- **执行联动**（PLAN-003 §2 同口径）：`execPlanCase` 标记功能用例（status∈PASS/FAIL 时）——查该用例前置用例集 ∩ 本计划 refs：存在最近结果=FAIL 的前置 → 响应附 `blockedBy:[{caseId,name}]`（提示层），默认建议 BLOCKED；用户强制提交其他状态也接受（blockedBy 仅提示不硬阻断）；标记 BLOCKED 时 result 记 `blockedBy` 留痕。后置不推导。
- **变更 diff 增强**：CaseUpdate 落 ChangeLog 时 diff 由「整对象快照」升级为分区摘要 `{ fields:[{key,from,to}], steps:{added,removed,changed} }`（变更历史 Tab 时间线按分区徽标渲染）；旧记录兼容（无 diff 结构时原样展示）。
- **选择器**：新增依赖弹窗数据=模块树+用例搜索（既有 list 端点复用），前端排除：自身 id、已在前置列表、已在后置列表（防即时互环）。

## 3. UI/UX 设计（高保真 docs/design/CASE-008-case-dependency-history/）

- 依赖 Tab：S1 双列表（前置/后置）+ 每列「添加」开选择器弹窗（左模块树+搜索框+右勾选列表+已选徽标）；行操作：移除、跳转用例。
- 成环提示：添加时 422 → Toast「将形成循环依赖：A → B → A」。
- 变更历史 Tab：时间线行分区徽标（字段/步骤/前置），字段级 from→to 行内展示。
- 计划执行侧（PLAN-003 联动呈现）：标记面板顶部黄条「前置用例未通过：{名称}，建议标记阻塞」+「仍要标记」按钮。
- 原型画板：①依赖 Tab+选择器弹窗 ②成环 Toast+自引用态 ③变更历史分区徽标+计划侧 BLOCKED 提示条。

## 4. 技术架构

- 数据模型：零迁移。
- 契约：`dependencyUpsertSchema` 复用；新增 `dependencyClosure` 服务函数（非契约）；execPlanCase 响应扩展 `blockedBy?`。
- 端点：既有 `POST/DELETE /cases/{caseId}/dependencies`（服务层加环检测）；无新端点。
- 服务：`caseV2.service.ts`（或 caseDetail.service）扩展 `assertNoCycle`（BFS 闭包）；`plan.service.execPlanCase` 联动查询（跨域读 FunctionalCase+CaseDependency 同域，直接查合规）；ChangeLog 写入侧 diff 分区化（caseV2 update 路径）。
- 错误码：`DEPENDENCY_CYCLE 50016`、`SELF_DEPENDENCY 50017`。
- 前端：依赖 Tab 选择器组件（复用 FunctionalCasePicker 骨架裁剪）；ChangeTimeline 分区渲染。
