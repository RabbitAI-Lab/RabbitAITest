## 1. 迭代目标

**把 MeterSphere X-Pack 的「社区版限制 + License 总开关」模型在标准版代码库内落地**：License 体系（添加/校验/到期提醒）作为企业版总门控，六大企业能力（多组织 / SSO / 多资源池 / 主题品牌 / 消息模板 / 用户扩容）全部经统一 `assertEntpEnabled(feature)` 门控挂接；社区版行为完全不变（1 组织 / 30 用户 / 1 默认池 / 固定模板 / 默认主题 / 账密登录）。

成功判定：

| 维度           | 目标                                                                                                                                    | 判定方式                                                    |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| License 总开关 | 添加有效 License 后六大特性逐一解锁；无效/过期/未授权特性→403 90xxx；社区版全量行为零回归                                               | 单测门控矩阵 + jmx 403 类 + e2e 解锁前后二态                |
| 多组织         | 组织 CRUD（建/编/结束/删）+ 顶栏组织切换器 + 项目按组织过滤；社区版不可建第二个组织                                                     | e2e 建组织→切换→过滤主链 + jmx 四类                         |
| SSO + 扫码     | LDAP/CAS/OIDC/OAuth2 四协议认证源 + 企微/钉钉/飞书扫码入口；mock IdP 全链可测；登录页「更多登录方式」                                   | e2e mock OIDC 自动授权登录 + 扫码登录主链 + 单测映射/状态机 |
| 主题品牌       | 界面设置（主题色/登录页定制/平台设置）实时预览→保存并应用；公开 theme 端点驱动全站                                                      | e2e 改主题色→登录页/控制台生效 + 恢复默认                   |
| 消息模板       | 11 事件自定义模板（变量插入/实时预览），dispatch 渲染挂钩，无模板回退默认                                                               | 单测渲染矩阵 + e2e 定制缺陷通知标题→触发→站内信按模板渲染   |
| 多资源池       | 池 CRUD（建/编/启停/删，应用组织）+ 按池队列路由（`exec-pool-{poolId}`（勘误 1：BullMQ 禁冒号））+ engine `POOL_ID` 绑定 + 执行选池下拉 | e2e 起 engine2 绑新池→场景选池执行成功 + 单测路由/心跳      |
| 用户扩容与部门 | License 放开 30 用户上限（payload.maxUsers 可选封顶）；组织级部门树 CRUD + 成员挂载                                                     | 单测上限矩阵 + e2e 部门树主链                               |
| 测试与交付     | 8 规格 ×（Vitest + JMeter 四类四断言 + Playwright 三类断言）全绿；远端 CI 全绿；OpenAPI 快照同步                                        | CI 六作业 + `gen-openapi --check`                           |

**本迭代不追求**：SAML 协议（枚举占位，验收环境缺失，登记后续）、K8S 型资源池的 kubectl apply 部署链（仅类型枚举+展示）、资源池 Controller 独立部署形态（以内置 web 调度替代）、企业版插件（协议插件/JIRA 增强——插件目录已具备上传机制）、UI 测试/性能测试模块（P4）、ARM64 安装包、License 在线授权/证书吊销（离线签名文件模型）。

## 3. 范围排除（防蔓延红线）

- **不做**：SAML 协议实现（AuthSource 枚举占位，`ENTP-002 §1.2` 登记后续）、K8S 池 kubectl 部署、独立 Controller 服务、真实三方扫码的企业账号侧配置（mock 授权链验收）、企业版插件上传联动（PLUG 体系已具备）、ENTP 前缀以外的任何新域表
- License 为**离线签名文件**模型：不做在线激活/吊销/到期宽限期续期；密钥经 env 注入，社区版行为 `NONE`
- 多组织不做：组织级配额、跨组织数据迁移、组织排序/收藏
- 多资源池不做：节点手动批量添加（IP:Port 表单——节点仍经 engine 心跳自动注册）、池间任务漂移/重调度、K8S Token/命名空间配置面
- 消息模板不做：多语言模板、渠道差异化模板（同一事件全渠道同一渲染）、模板变量自定义函数
- 主题不做：暗色模式、多主题套包、租户级主题（仅系统级一套）
- 用户扩容不做：邮箱邀请注册流（沿用管理员创建）、部门级权限（部门仅组织维度，不挂权限点）

## 4. 验收标准（现场跑通）

1. 授权管理：`/system/license` 添加开发签发 License → 状态卡转「企业版 · 有效期至 N」→ 功能矩阵六项全亮；删除 → 回「社区版」
2. 门控二态：无 License 时新建资源池/组织/模板保存/界面设置保存/认证源保存 → 403 90001（前端按钮禁用+提示）；加 License 后全部放行
3. 多资源池：新建池「企业池」→ spec 内起 engine2（`POOL_ID`）→ 池卡片节点 ONLINE → 场景执行选「企业池」→ 任务 SUCCESS 且报告/任务详情池=企业池；默认池不可删不可禁用
4. 多组织：新建组织（指定管理员）→ 顶栏切换器出现 → 切换后项目列表只剩该组织项目 → 结束组织 → 不再出现在切换器
5. 用户扩容：License（maxUsers=1000）下创建第 31+ 用户成功；删除 License 后第 31 个用户创建 → 10151
6. 部门：组织部门页建两级树 → 挂成员 → 成员列表可见；子部门非空不可删
7. 主题：界面设置改主题色+登录 Slogan+平台名称 → 预览即变 → 保存并应用 → 登录页/顶栏/主按钮色即时生效 → 恢复默认
8. 消息模板：缺陷事件模板标题改 `[${project}] ${actorName} 提交了缺陷 ${title}` → 触发缺陷创建 → 站内信按模板渲染；无模板事件回退默认文案
9. SSO：配置 OIDC 认证源（指向 mock IdP）→ 登录页「更多登录方式」出现 → 点击 → mock 自动授权 → 回调登录成功（用户 source=OIDC）；LDAP 表单直登走 bind 校验（单测 fake 覆盖）
10. 扫码登录：配置钉钉认证源（指向 mock）→ 登录页扫码入口 → mock 授权中转 → 回调登录成功
11. 社区版零回归：全量单测 / JMeter / Playwright 既有用例全绿（重点 EXEC-002 池页、SYS-004 用户、SYS-005 参数、MSG-001 消息）
12. 自动化测试齐备（rules/testing.md）：8 规格 ×（Vitest + JMeter 四类×四断言 + Playwright 三类断言）全绿；远端 CI 全绿；OpenAPI 快照 `--check` 过

### 7.2 交付过程中发现并修复的缺陷（实现侧）

1. **BullMQ 队列名禁含冒号**：设计稿 `exec:{poolId}` 启动即抛「Queue name cannot contain :」→ 改 `exec-pool-{poolId}`（shared 同源函数，ENTP-006 勘误 1）
2. **SSO redirect_uri 取 base.siteUrl 默认 :3000**：与实际部署端口不一致 → 改取发起请求 origin（部署免配置，ENTP-002 勘误）
3. **CAS XML 属性 `cas:` 前缀未剥离**：fast-xml-parser 解析后映射落空 → 归一化去前缀
4. **mock IdP 路由段数不齐**：钉钉 `oauth2/userAccessToken`/`contact/users/me`、飞书多段路径、企微 `gettoken` 未覆盖 → 404 文本被当 JSON 解析致 500 → 补齐多段路由
5. **ENTP-005 preview POST 被兄弟动态段 `[event]` 405 吞并** → 迁静态子路由 `preview/`
6. **ENTP-008 createDepartment 环检测误传参**：parentId 误作 departmentId → 所有子部门创建 90042 自环假报 → 改为仅校验父属组织
7. **EXEC-002 与 ENTP 并行持证竞态**：license-status 读态与按钮态窗口错位 → 读态↔按钮态一致重试环（≤30s）
8. **ENTP-007-02 断言竞态（CI r3 暴露）**：篡改 License 提交的 `getByText("90003")` 误匹配弹窗脚注提示，在 422 响应到达前通过并跑完 Console 断言（响应事件未及记录）→ 改锚定 `.ant-message` 错误本体（验签失败文案=响应已到的证据）+ 422 预期负路径白名单登记
9. **SYS-007 local-runner 存量竞态（S5 代码，CI 慢机暴露）**：查询首达无条件 `setAddress(q.data.address)`，晚于用户 fill 时服务端 null 清空已填地址→检测按钮 disabled → dirty 标志守护（用户编辑后不再用服务端值覆写）

### 7.3 生成器与栈教训（jmx 调试 11 轮复盘）

- **JMeter Cookie/变量不跨线程组**：G0 组登录的会话与提取的变量在 G1 不可用（401/`${VAR}` 原样发出致 URISyntaxException）——每个 admin 操作组须自带登录+License 幂等覆盖（adminRelogin 片段）、跨组数据全部组内自备（注册成员/取组织/项目）
- **mock 绝对 URL 直连断言撤除**：JMeter 绝对 URL 请求经本机代理环境不稳（503）——mock IdP 链路断言归 e2e 全链覆盖（ENTP-002/003 §5 勘误登记）
- **断言信封路径**：列表端点断言须 `$.data.items[...]`（信封内），`$[0]` 顶级数组写法仅适用于裸数组响应
- **License 状态是全局共享态**：jmx 计划按字母序串行执行，ENTP-004/007 计划负责社区态收尾/清理，其余计划 G0/G4 幂等覆盖保证企业态
- **next 动态段吞并**：`[event]` 动态段会吞并同位置 POST（405）——语义化子路径须建静态段路由
- **TypeScript noUncheckedIndexedAccess**：config Json 值一律经 `S()` 安全取串，`Buffer.from(parts[1] ?? "")` 等 undefined 防御
