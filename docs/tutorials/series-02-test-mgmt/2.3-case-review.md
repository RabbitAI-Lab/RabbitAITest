# 2.3 用例评审

| 项          | 值                                                 |
| ----------- | -------------------------------------------------- |
| 集号 / 系列 | 2.3 / 系列二 · 测试管理                            |
| 目标时长    | 4:00（±20s）                                       |
| AI 素材     | `broll-intro`（复用）+ `broll-2.3`（概念动画 10s） |
| 涉及路由    | `/reviews`、`/reviews/[id]`、`/cases`              |
| 状态        | 已成片（2026-10-10 v1）                                             |

## 教学目标

看完本集，观众能够：发起一场用例评审、作为评审人逐条给出通过/驳回与意见、查看评审结论回流到用例状态，并理解评审与消息通知的联动。

## 录制数据准备

- 预置 2 个账号：评审发起人（admin）与评审人（reviewer01，组织成员）；6~8 条待评审用例。
- 参考造数：`tests/e2e` 中评审模块用例（CASE/RVW 前缀，以实际文件名为准）。

## 配音脚本

| 镜号 | 文案                                                                                                 |
| ---- | ---------------------------------------------------------------------------------------------------- |
| S2   | 一份用例就像一张蓝图，评审就是让多束目光同时照向它，逐块确认，直到整图点亮。                         |
| S3   | 发起评审：圈选要评审的用例，指定评审人，一场评审就建好了。                                           |
| S4   | 以评审人的身份进入评审单，逐条阅读：认可的直接通过；有问题的驳回并写下具体意见。每一条结论都有留痕。 |
| S5   | 评审结束后回到用例库——被驳回的用例状态已经变化，作者能第一时间看到哪些用例需要修改。                 |
| S6   | 与此同时，评审分配与驳回结论都会以站内消息触达相关人。评审不是孤立动作，而是带着通知的协作闭环。     |
| S7   | 发起、逐条评审、状态回流、消息触达——这就是用例评审的完整闭环。                                       |

## AI 素材提示词

### broll-2.3（T2V · 768P · 10s · Hailuo 2.3）

扁平低多边形3D插画风格，深蓝色科技空间背景（由深靛蓝到暗夜蓝的柔和渐变），主体以靛蓝色 #2545eb 与白色发光材质为主，辅以青色粒子光效点缀，电影级柔光，画面干净克制，无人物。一张巨大的发光蓝图悬浮在画面中央，四束来自不同角度的锥形光束同时投向蓝图，被照到的区域逐块由线框变为实心发光体；随后一枚青色圆形印章光效从上方缓缓落下，盖在蓝图一角激起一圈光环，蓝图整体亮度提升一级并轻微旋转展示。镜头先缓慢推近再环绕四分之一圈。

负面提示：画面中不得出现任何文字、字母、数字、单词、Logo、UI 界面、按钮、水印、签名；不要人脸特写、不要畸变的手部、不要闪烁噪点、不要低分辨率噪感


## 勘误 1（2026-10-10 实现对照）

- 新建评审弹窗无用例圈选（用例创建后在详情页关联）；预置评审已终态，通过/驳回二态以结论回流 Tab 呈现

## 录制要点

- 双账号段（S4~S6）用两个浏览器 profile 分别登录录制，剪辑时交叉切换；避免同浏览器反复登出的等待。
- S5 的状态二态对比是本集关键断言画面，截取前后同位置同缩放的两段，剪成 1s 对切。
