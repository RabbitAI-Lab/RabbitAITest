## 1. 迭代目标

**一句话定调：把「写测试的人」与「看结果的人」连起来——事件发生即通知（站内信/邮件/三方机器人），协作动作（@提及/关注/处理人）有回声，个人有一站式中心；同时补齐环境组/全局参数/公共脚本/Git 仓库四个项目级协作基建。**

端到端可演示路径（浏览器操作主线）：

```
登录 admin → 项目设置-消息管理：新建钉钉机器人（webhook 指向 mock，测试消息发送成功）
  → 缺陷页创建缺陷并流转 → 顶栏铃铛出现未读（创建+流转两条站内信，操作人本人去重）
  → mock 机器人端点收到 webhook 投递
  → 缺陷评论 @项目成员 → 对方铃铛收到提及通知
  → 缺陷删除 → 回收站可见 → 批量恢复 / 勾选彻底删除
  → 项目设置-公共脚本：新建脚本（定义参数）→ 在线调试控制台输出 → 发布
  → 接口用例前置处理器引用公共脚本 → 执行 → 报告步骤日志含脚本输出
  → 项目设置-环境管理：编辑全局参数 → 新建环境组（勾选两个环境）
  → 场景批量执行选环境组 → 任务列表生成 2 个任务（按组内顺序，任务名带环境名）
  → 文件管理：连接 Git 仓库（platform+url+token，连接测试）→ 按分支+路径拉取 → 文件列表带仓库标识
  → 文件删除 → 回收站恢复
  → 个人下拉-个人中心：改姓名/手机 → 修改密码（旧密码错误 422 → 正确后新密码可登录）
  → 本地执行配置（环回地址连通检测）→ 个人默认模型 → AI 助手按个人模型应答
```

四条成功判定：

| 维度     | 目标                                                               | 判定方式                                        |
| -------- | ------------------------------------------------------------------ | ----------------------------------------------- |
| 功能完整 | 6 规格 §1.2 全部 P1 ✅ 能力行交付                                  | 规格 §5 用例 ↔ tests/ 一一对应全绿；能力行审计  |
| 事件闭环 | 缺陷/评审/计划/执行/定时五类事件 → 站内信+机器人投递，同人去重生效 | e2e：触发事件后铃铛未读数与 mock 机器人收包断言 |
| 协作回声 | @提及/关注变更/回收站批量操作可用                                  | e2e：被提及人收到通知；回收站批量恢复后列表回归 |
| 质量门禁 | Vitest / JMeter / Playwright 全绿 + 远端 CI 六作业全绿             | CI run 全绿；OpenAPI 快照 diff 通过             |

**本迭代不追求**：自定义消息模板（ENTP-005 红线）、多语言脚本引擎（quickjs-only，登记 Backlog）、Git 仓库整树定时同步、三方平台个人账号绑定（架构口径冲突，登记 Backlog）、邮箱邀请注册/Excel 批量导入（再次顺延，登记 Backlog）。

## 3. 范围排除（防蔓延红线）

- 不做：自定义消息模板与变量插入（【企业版】ENTP-005，P2 红线）；机器人加签 secret（Robot 表无密钥列，登记 Backlog）；通知跳转深链（Notification 无来源列，登记 Backlog）
- 不做：python/groovy/beanshell 多语言公共脚本（引擎 quickjs-only）；脚本引用 JAR（JS 沙箱无 JVM classpath，PROJ-004 登记口径延续）
- 不做：Git 仓库定时整树同步、子模块、PR/MR 集成；仓库文件版本对比
- 不做：三方平台个人账号绑定（与 INTG-001 组织级凭据架构冲突，登记 Backlog）；邮箱邀请注册/Excel 批量导入用户（SYS-004 域，顺延登记）
- 不做：个人主题/时区（主题=ENTP-004 红线）；界面语言切换（全局 i18n 超范围，Backlog）
- 兼容承诺：S1-S7 全部既有端点与契约不变；执行契约 processor 新增可选 `scriptRef` 字段为 additive 变更（v4 兼容）
- 本地缺陷删除不推送三方平台关闭（INTG-001「删除同步延后」口径在 BUG-002 显式重申）

### 7.2 交付过程中发现并修复的缺陷

- 机器人 webhook http 协议被拒（422 20441）→ `validateWebhook` 协议比较漏冒号（`"http"` vs `"http:"`，https 恰好通过掩盖）→ 补冒号 → e2e T2 复绿
- Git 仓库连接测试/拉取 ECONNREFUSED 127.0.0.1:80 → `parseRepoUrl` 用 `url.hostname` 丢端口，apiBase 落默认 80 端口 → 改用 `url.host`（官方域名判断保留 hostname）→ 单测矩阵 + e2e T2 复绿
- mock Git 平台缺 repo 元信息端点（`{apiBase}/repos/{o}/{r}`）→ adapter 契约四端点未对齐 → 补 gitea/github/gitee 元信息端点 → 连接测试 200
- 公共脚本在线调试 500（`a is not a function`）→ quickjs-emscripten（wasm 动态加载）被 Next server 打包破坏 → `serverExternalPackages` 增列 → 调试端点 200（n=6 参数覆盖生效）
- 个人中心表单不回填 → antd Form `initialValues` 仅首帧生效，异步 me 查询后未 set → `useEffect` setFieldsValue → e2e T2 回显断言复绿
- 预防性：web 出站 fetch 显式 `cache: "no-store"`（Next GET 数据缓存层对外站请求的潜在粘滞，SSRF/机器人/Git 三处统一）
- gen-jmx-s5 生成器三连缺陷（本地三轮定位）：①TestPlan UDV elementProp 误写驼峰 `user_definedVariables`——JMeter 仅认下划线，整块 UDV 被忽略致 `${EMAIL}` 原样发出（T0 全线 422）；②UDV 值自引用 `${TS}` 污染整区 UDV 求值；③断言用假 uuid 13 位（`000000000dead`）且 zod `.uuid()` 校验 RFC 版本位（第三段须 1-5、第四段 8/9/a/b）——统一改合法版本位 12 位
- jmeter 栈 api-test-stack.sh 未透传 MOCK_PORT（API-011 同步 URL 属性缺省回落 4000，此前靠开发栈 mock 残留兜底假绿）——补 `MOCK_PORT=$JM_MOCK_PORT`

- CI 首红①（BUG-001 三用例稳定红）：bugs 页回收站 testid 误改 `tab-bug-recycle` 破坏既有用例——本地全量假绿根因=/tmp/rabbit-e2e-root 旧构建副本被 webServer 优先启动掩盖改名（副本已删+勘误：**副本构建与仓库构建不一致时须删副本重验**）；testid 恢复 `tab-recycle` 沿用 BUG-001
