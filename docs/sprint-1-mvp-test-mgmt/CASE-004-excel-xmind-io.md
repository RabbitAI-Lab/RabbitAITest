## 1. 概述

### 1.1 功能定位

存量用例迁移的主通道：Excel（业务批量）与 Xmind（结构化脑图）双向。导入向导三步式（上传→映射确认→结果报告）沉淀为通用组件。

### 1.2 范围边界

| 能力                                                                                                                    | P1 ✅ | 后续                                       |
| ----------------------------------------------------------------------------------------------------------------------- | ----- | ------------------------------------------ |
| Excel 导入：xlsx 解析、模板下载（含动态字段列头）、ID（num）相同=覆盖/跳过策略、校验报告（错误行号+原因）、目标模块选择 | ✅    | 导入触发评审/计划的连带更新                |
| Xmind 导入：v2.x（zip/content.json）、模块→用例→步骤树映射、同名模块合并策略                                            | ✅    | 旧版 XML 格式（遇样例再补）                |
| Excel 导出：默认格式/单元格拆分格式、字段选择（静态+动态）、按当前筛选/勾选导出                                         | ✅    | 异步大导出任务（万级行走任务中心 SYS-006） |
| Xmind 导出：按模块树结构导出（标记/备注承载前置与预期）                                                                 | ✅    | 导出样式模板                               |
| MeterSphere 模板兼容：官方 Excel 模板列识别映射                                                                         | ✅    | Xmind 官方样式细节 100% 还原（按样例回归） |

CASE-002 树与列表合入；导入导出同步执行（行数上限 5000，超限 422 提示等待异步任务——Sprint 6 后开放）。

完全复刻：双格式、覆盖/跳过、模板下载、导出两种 Excel 格式与字段选择。简化实现：P1 同步执行有 5000 行上限（基线异步任务制）；Xmind 优先 v2.x。

## 2. 业务逻辑

- 导入映射：列头→字段（固定列用名称匹配别名表：如「用例名称/名称」）；无法识别列进「忽略列」清单（报告中明示）。
- 覆盖语义：按 num 匹配存量（含回收站？否——回收站不参与）；覆盖=白名单字段全量替换 + ChangeLog(action=import_overwrite)；跳过=计数不动数据。
- Xmind 结构：根主题=项目名（忽略）、一级分支=模块（路径式创建/合并）、叶子前文本块=步骤（备注=预期、标签=前置优先级：优先级图标→等级，标签文本→tags）。
- 校验规则复用 buildValidator（动态字段）+ 静态校验（等级枚举/步骤非空/长度）；全部行先校验后落库（fail-fast 报告，不产生半量导入）。
- 导出文件名：`{项目名}-用例-{yyyyMMddHHmm}.xlsx|xmind`；导出记录操作日志。

## 3. UI/UX 设计（高保真 docs/design/CASE-004-excel-xmind-io/）

- 入口：列表工具栏「导入/导出」按钮 → 导入向导 Modal 三步：①上传区（拖拽、模板下载链接、格式说明折叠）②预览映射（前 20 行表格、列映射下拉、覆盖/跳过单选、目标模块树选择）③结果报告（成功 N/失败 M、失败行明细表、错误定位原因、重新上传按钮）。
- 导出 Modal：格式单选（Excel 默认/Excel 拆分/Xmind）、字段勾选清单（分组：基础/步骤/动态字段）、范围（当前筛选/勾选行）。
- 大文件态：解析中 loading 与进度条（前端模拟分段）；超限 422 明确文案。

## 4. 技术架构

- 选型：Excel=exceljs（读写）；Xmind=自研 zip 解析（fflate）+ content.json 映射；无跨域依赖。
- 端点：`POST /api/v1/projects/{pid}/cases/import`（multipart：file+mode+moduleId+mapping）、`GET /api/v1/projects/{pid}/cases/import/template`（模板下载）、`POST .../cases/export`（JSON 体→文件流）。
- zod：importOptionsSchema（mode=overwrite|skip）、exportOptionsSchema（format/fields/scope）。
- 权限点：PROJECT_CASE:CREATE（导入）、PROJECT_CASE:READ + PROJECT_REPORT:EXPORT 语义（导出，随本规格入库 PROJECT_CASE:EXPORT 简化为 CREATE/UPDATE/READ 复用——评审定夺，默认 READ）。
- 服务：`caseIoService`（纯函数解析/组装可单测）+ 流式写出（内存上限保护）。
- 前端：`<ImportWizard/>`（三步状态机，Sprint 2+ 其他导入复用）。

## 5. 测试用例

- CASE-004-T1（jmx 四类）：导入合法文件 200+信封（成功计数）；未登录 401；无 CREATE 权限 403；坏文件/超限 422；模板下载 200 content-type 断言。
- CASE-004-T2（spec 主链路）：下载模板→填 3 行（1 行等级非法）→导入向导走完→报告 2 成功 1 失败（行号定位）→列表模块下出现 2 条（UI+接口）；再导入同 ID 覆盖模式→记录数不变字段更新。
- CASE-004-T3（spec）：Xmind（ fixture 文件）导入→模块树结构出现→导出 Xmind→重新导入 roundtrip 行数一致。
- 单测：列别名映射表、覆盖/跳过、Xmind 树映射、5000 行上限、Markdown 转义。
