## 1. 概述

### 1.1 功能定位
项目是业务数据的隔离边界（SYS-002 已强制 project 过滤）。本规格补齐：项目内成员与用户组管理、项目信息编辑（含模块开关）、项目软删与 30 天撤销。

### 1.2 范围边界

| 能力 | P1 ✅ | 后续 |
| --- | --- | --- |
| 项目信息：名称/描述编辑、模块开关（用例/计划/缺陷等，关闭=菜单隐藏数据保留）、启用状态 | ✅ | 项目版本（后续迭代） |
| 成员管理：从组织用户搜索添加、移除、批量添加；成员列表（用户/组/加入时间） | ✅ | 跨项目批量迁移 |
| 项目级用户组：自定义组 CRUD + 权限点勾选（复用 SYS-004 组件 scope=project） | ✅ | — |
| 组织级项目列表：新建/编辑/进入/结束（结束=只读）/删除（软删 30 天，期间可撤销） | ✅ | — |
| 项目切换器显示成员项目集合 | ✅（增强 SYS-003） | 全组织项目浏览（组织管理员） |

### 1.3 前置依赖
SYS-004 合入（组组件与检查链）。

### 1.4 对标基线核对
完全复刻：模块开关数据保留语义、删除 30 天可撤销、成员+组两级管理。简化实现：基线「批量操作」本迭代覆盖批量加组成员；跨项目批量迁移登记后续。

## 2. 业务逻辑

- 进入项目前置：用户是项目任一组成员（或组织管理员）；否则项目切换器不出现该项目，直访 URL 返回 404（SYS-002 已有 project scope，本规格补成员判定数据源）。
- 模块开关关闭：路由守卫重定向工作台 + 菜单隐藏；数据与端点保留（写操作仍按权限放行，与基线「数据保留」口径一致，仅 UI 收敛）。
- 项目删除：软删（deletedAt）→ 30 天后由清理 job 物理删除（级联）；期间「撤销」恢复。删除与撤销均写操作日志。
- 「结束」状态：只读（写端点统一 422 code 10005 PROJECT_ENDED）。

## 3. UI/UX 设计（高保真 docs/design/PROJ-001-project-permission/）

- 组织 › 项目管理：表格（名称/成员数/状态/创建时间/操作：进入·编辑·成员·结束·删除）；删除需 Modal 二次确认并明示「30 天内可撤销」。
- 项目 › 设置 › 成员管理：左成员表（搜索添加、移除）；右「用户组」入口（复用组管理组件）。
- 项目 › 设置 › 基本信息：名称/描述/模块开关（Switch 列表）/启用状态。
- 项目切换器：仅显示成员项目；组织管理员显示全部并带「管理员」角标。

## 4. 技术架构

- 数据模型（已建齐）：Project(name/description/module_flags JSONB/status/deletedAt)、GroupMember(scope=project, scope_id=project)。
- 端点：`GET/POST /api/v1/orgs/{org}/projects`、`PUT /api/v1/projects/{pid}`、`POST /api/v1/projects/{pid}/close|reopen`、`DELETE /api/v1/projects/{pid}`（软删）、`POST /api/v1/projects/{pid}/restore`；`GET/POST /api/v1/projects/{pid}/members`、`DELETE .../members/{userId}`。
- zod：projectUpsertSchema、moduleFlagsSchema（已知模块枚举）。
- 权限点：ORG_PROJECT:CREATE|UPDATE|DELETE（组织级）；PROJECT_GROUP:*（项目级）；成员管理=PROJECT_MEMBER:UPDATE（随本规格入库）。
- 前端：设置页 `/settings/*`；切换器数据源改 `/personal/projects`（服务端已按成员过滤）。
