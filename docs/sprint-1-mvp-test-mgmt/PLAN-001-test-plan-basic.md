测试执行的组织单元：计划=用例集合+执行配置+执行结果聚合。P1 落「功能用例计划」闭环（接口/场景关联与测试点分层在后续迭代扩展，模型一次建齐已预留 ref_type）。

## 2. 业务逻辑

- 执行状态机（PlanCaseRef.exec）：`pending → (pass|fail|blocked|skipped)`；可重新执行（任意终态→pending→再标记）；每次标记记执行历史（时间+人+旧→新+步骤结果 JSONB）。
- 通过率：`pass / (pass+fail+blocked)`（skipped 不计分母；pending 全集展示为进度）；阈值判定=通过率≥阈值。
- 步骤结果：FunctionalCase.steps 数组逐条对位；失败步骤标红并作为「新建缺陷」带出内容。
- 自动更新状态开关 P1 语义：仅存配置（对齐基线设置项），生效逻辑随 CASE-006 联动实现时激活（登记去向，避免假实现）。
- 归档：archived_at 置位 → 全部写端点 422（code 10008 PLAN_ARCHIVED）；执行结果与报告只读。
- 重复关联开关：关闭时同用例二次关联 422（code 10009 DUP_ASSOC）。

## 3. UI/UX 设计（高保真 docs/design/PLAN-001-test-plan-basic/）

- 左导航「测试计划」：列表页（表格=名称/模块/用例数/执行进度条/通过率+阈值徽标/状态（未开始/进行中/已归档）/起止/操作：进入·归档·编辑·删除）。
- 计划详情页：头部（名称+状态+通过率环形+阈值说明+「更多设置」入口+归档按钮）；Tab=用例清单 / 报告。
- 用例清单 Tab：工具条（关联用例/批量改执行人/筛选：状态·执行人·模块）；表格行展开=步骤级执行面板（每步：结果三态按钮组+实际结果输入）；行内快捷操作（标记结果五态下拉、缺陷关联/新建图标、评论图标抽屉）。
- 新建缺陷弹窗：BUG-001 表单组件嵌入（预填标题/失败步骤/关联）。
- 报告 Tab：最小报告（通过率卡+用例结果汇总表+总结 Markdown 编辑保存）。
- 归档确认 Modal（明示只读）；已归挡详情页顶部黄色横幅。

## 4. 技术架构

- 数据模型（已建齐）：TestPlan(module/plan_dates/settings JSONB/archived_at)、PlanCaseRef(plan/ref_type=case/ref_id/executor/exec_status/result JSONB/exec_history JSONB)、PlanReport(summary/threshold_result)。
- 端点：`GET/POST /api/v1/projects/{pid}/plans`、`GET/PUT/DELETE .../plans/{id}`、`POST .../plans/{id}/archive|unarchive`、`POST .../plans/{id}/cases`（批量关联）、`DELETE .../plans/{id}/cases/{refId}`、`POST .../plans/{id}/cases/{refId}/exec`（状态+步骤结果+实际结果+评论）、`POST .../plans/{id}/cases/batch-executor`；`GET .../plans/{id}/report`、`PUT .../plans/{id}/report/summary`。
- zod：planUpsertSchema、planSettingsSchema（dup_assoc/auto_update/threshold 0-100）、planExecSchema（状态枚举+步骤结果数组对位校验）。
- 权限点：PROJECT_PLAN:READ|CREATE|UPDATE|DELETE（EXECUTE 权限点随 PLAN-003 引擎执行启用，人工标记=UPDATE）。
- 聚合：通过率为查询时聚合（CTE 单查询），不落冗余（万级内足够，性能线验证）。
- 前端：`/plans/*` 路由组；步骤执行面板组件 `<StepExecPanel/>`；环形图复用 CASE-005。
