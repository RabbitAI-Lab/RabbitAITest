## 1. 概述

### 1.1 功能定位

登录后的默认落地页：把分散在各域的「与我有关」的数据聚合成看板与三视图，让每个角色 10 秒内知道「今天该做什么」。

### 1.2 范围边界

| 能力                                                                                                           | P1 ✅ | 后续                                   |
| -------------------------------------------------------------------------------------------------------------- | ----- | -------------------------------------- |
| 首页看板：当前项目概览卡（用例总数/本周新增、评审通过率、计划执行进度 Top3、缺陷待处理数/本周新增）            | ✅    | 接口域卡片（Sprint 2 后）              |
| 时间筛选：近 3 天/近 7 天/自定义区间（作用于「新增」类指标）                                                   | ✅    | 自动刷新                               |
| 项目选择：切换器联动（沿用 SYS-003）                                                                           | ✅    | 全项目汇总视图                         |
| 卡片设置：每卡不展示/半屏/全屏（布局偏好持久化）                                                               | ✅    | 拖拽排序                               |
| 我的待办：待我评审（未评）、我的计划执行（pending 且执行人=我）、我的缺陷（处理人=我且非结束态），按域筛选 Tab | ✅    | 定时任务待办（SYS-006 后）             |
| 我关注的：关注实体列表（用例/计划/缺陷），带最近变更时间                                                       | ✅    | 接口用例/场景/评审关注维度（DASH-002） |
| 我创建的：我创建的用例/评审/计划/缺陷，筛选同上                                                                | ✅    | —                                      |

### 1.3 前置依赖

B/C 线域功能合入（本规格是纯消费者）；聚合端点各域 Provider 就位。

### 1.4 对标基线核对

基线 §三全项对齐（P1 数据源仅测试管理域；基线的接口域维度随 Sprint 2 数据就绪补齐——登记 DASH-002）。简化实现：基线「页面自动刷新」延后（低价值高干扰，登记勘误候选）；卡片设置三态对齐。

## 2. 业务逻辑

- 看板口径：本周新增=createdAt ∈ 筛选区间；评审通过率=项目内未结束评审的加权（Σpass/Σ已评）；计划进度=进行中计划的 Σ已执行/Σ关联；缺陷待处理=status 非结束态。
- 待办判定（与各域状态机一致）：待我评审=ReviewCase.reviewers∋me 且 result=pending 且评审未结束；我的执行=PlanCaseRef.executor=me 且 exec=pending 且计划未归档；我的缺陷=handle_user=me 且状态非结束。
- 聚合端点单请求返回全部卡片（避免前端 N+1）；待办/关注/创建分页端点按域。
- 跨域读取一律经各域 Provider 接口（test-domain-model §3），dash 域不直查他域表（CI boundaries 检查覆盖）。

## 3. UI/UX 设计（高保真 docs/design/DASH-001-workbench-home/）

- 页面（路由 `/`，替换 Sprint 0 占位首页）：顶部=项目切换器（顶栏已有）+ 时间筛选 Segmented + 卡片设置齿轮（Popover：每卡三态单选）。
- 看板栅格：2 列响应式；卡片=标题+主数字+副指标+趋势箭头；半屏卡占 1 格、全屏 2 格、不展示即隐藏（布局记忆）。
- 下方三视图 Tabs：我的待办（红点计数）/我关注的/我创建的——列表式（图标+标题+所属域标签+关键状态+时间），点击直跳各域详情；域筛选 chips。
- 空态：新用户引导卡（建用例/建计划/邀成员三入口）。

## 4. 技术架构

- 数据模型（已建齐）：无新表；卡片布局=user_preference JSONB；Follow 复用。
- 端点：`GET /api/v1/projects/{pid}/dashboard/overview?range=`（聚合卡）、`GET .../dashboard/todo?kind=&page=`、`GET .../dashboard/followed?page=`、`GET .../dashboard/created?page=`。
- Provider：case/plan/bug 域各暴露 `StatsProvider`/`TodoProvider`（packages/shared 接口 + web 域内注册），dash service 只依赖接口（门禁 5 解耦）。
- zod：overviewResponseSchema（卡片判别联合）、rangeSchema（3d/7d/custom+起止）。
- 权限点：登录即可（项目内=PROJECT_*:READ 并集随数据源自然过滤；无读权限的域该卡片返回 null 前端隐藏）。
- 前端：TanStack Query 并行拉取；卡片组件注册表（新域卡片即插即用）；数字动画（AntD Statistic）。

## 5. 测试用例

- DASH-001-T1（jmx 四类）：overview/todo 端点；401；跨项目 404；非法 range 422；分页信封。
- DASH-001-T2（spec 主链路）：造数（1 条待我评审+1 条我的 pending 执行+1 条我的待处理缺陷）→ 待办 Tab 三条与跳转正确（UI+接口断言口径字段）→ 处理一项后刷新计数减一。
- DASH-001-T3（spec）：时间筛选近 3 天→本周新增数字变化；卡片设为不展示→刷新后布局记忆（user_preference 断言）。
- 单测：各口径聚合 SQL（边界：区间闭开、空集除零）、Provider 注册完整性。
