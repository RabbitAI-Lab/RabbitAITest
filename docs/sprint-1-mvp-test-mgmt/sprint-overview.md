## 1. 迭代目标

**8 周「测试域核心可用」的第一半：把 Sprint 0 的单薄用例 CRUD 升级为完整测试管理 MVP。**

端到端可演示路径（浏览器操作主线）：

```
管理员配置用户组权限 → 项目启用模板与自定义字段 → 用例按模块树组织（Excel 导入）
→ 创建评审并逐条评审（通过率）→ 创建测试计划并关联用例 → 列表模式执行（S/E/B）
执行失败一键建缺陷（模板+工作流流转）→ 计划通过率 → 工作台看板汇总
```

三条成功判定：

| 维度 | 目标 | 判定方式 |
| --- | --- | --- |
| 权限正确性 | 三级用户组 + 权限点勾选端到端生效 | 无权限点用户访问对应端点 403（10003），前端按钮隐藏 |
| 模板动态性 | 自定义字段在用例/缺陷表单-列表-详情三处一致渲染；缺陷工作流按矩阵流转 | 模板变更后新实例按新校验、存量不回写 |
| 测试管理闭环 | 模块树→导入→评审→计划→执行→缺陷→看板全链路 | Playwright 主链路 E2E 全绿 |

**本迭代不追求**：脑图（Sprint 4）、三方平台同步（Sprint 5/6）、计划测试点与完整报告（Sprint 4）、富文本重型编辑器（受限 Markdown 即可）。

## 3. 范围排除（防蔓延红线）

- 不做：脑图任何形态（CASE-007）、三方需求/缺陷同步（INTG-001/002）、计划测试点与完整报告导出（PLAN-002/005）、定时任务（SYS-006）、消息通知（MSG-001）、接口域一切功能（Sprint 2）
- 不做任何 ENTP 功能；计划组=企业版口径（清单 §12.7），社区版仅普通计划
- 用户邮箱邀请与 Excel 批量导入用户延后（依赖 SMTP 联调与批量基建，Sprint 5+）
- 富文本采用受限 Markdown 子集（粗体/斜体/列表/链接/代码块），不引入 CKEditor 级重型编辑器

## 4. 验收标准（现场跑通）

1. 自定义用户组仅勾选 `PROJECT_CASE:READ` 的用户：用例列表可见、新建按钮隐藏、直发 POST 返回 403（code 10003）
2. 组织定义「严重程度」单选字段并绑定用例模板 → 用例表单出现该字段且必填生效 → 列表可按该字段筛选 → 存量用例编辑前不受影响
3. 缺陷工作流：新增「挂起」状态与允许矩阵 → 不允许的流转被拒（422）→ 列表状态色点与待处理统计正确（结束态不计）
4. 模块树拖拽移动节点 → 用例列表随模块过滤；Excel 导入 50 条（含 2 条校验失败）→ 校验报告明确定位行号
5. 多人评审：2 评审人全部通过才通过；任一失败即失败；重新提审后状态回到待评审
6. 计划执行：列表模式标记失败 → 弹窗新建缺陷自动带出失败步骤 → 缺陷关联可见 → 计划通过率实时更新 → 归档后只读
7. 工作台看板数字与各域列表一致（时间筛选生效）
8. 自动化测试齐备（rules/testing.md）：每功能点 Vitest + JMeter（四类场景×四项断言）+ Playwright（UI/Console/接口三类断言）全绿；新增主链路 E2E（模块树→导入→评审→计划→执行→缺陷→看板）
9. Sprint 收尾交付（AGENTS.md 门禁 9）：commit + push 远程、远端 CI 全绿、本概览交付表更新、changelog 追加

## 6. 风险与预案

| 风险 | 预案 |
| --- | --- |
| 动态字段筛选性能（fields JSONB） | GIN 索引 + 高频字段（severity/status）冗余列；万级用例筛选 < 1s 为验收线 |
| Xmind 格式解析（zip+content.json 版本差异） | 优先支持 v2.x（content.json）；旧版 XML 遇样例再补，导入失败走校验报告不阻塞 |
| 权限并集/禁用交集语义复杂 | 以 rbac-permission-model §1 为准写契约测试（矩阵用例），先测后改 |
| 9 Tab 范围蔓延 | CASE-003 明确 P1 子集与 ❌ 去向，评审时逐条核对 |
| SMTP 真实投递联调不稳定 | 测试连接 + 日志留证；真实发信仅验收演示一次 |
