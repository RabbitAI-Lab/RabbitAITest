## 1. 概述

### 1.1 功能定位

所有后台执行任务的统一观测与操作台。S2 承接实时任务（api_debug/api_case）全量能力；定时任务交付框架空态（数据源 S3+ 逐迭代接入）。

### 1.2 范围边界（能力行 → §5 用例映射）

| 能力                                                                       | P1 ✅ | 后续                                        |
| -------------------------------------------------------------------------- | ----- | ------------------------------------------- |
| 实时任务列表：范围 Tabs（本项目/全部项目（我可见项目））；筛选 类型/状态/创建人/时间区间；列：任务/类型徽标/状态/进度(item 通过÷总数)/创建人/开始/耗时/操作 | ✅     | 组织级独立 Tab（单组织部署口径合并，登记） |
| 行操作：查看报告（跳 /reports/{taskId}）/停止（RUNNING）/重跑（FAILED/STOPPED）；「重跑自」溯源列 | ✅     | —                                           |
| 运行中刷新：有 RUNNING 任务时 3s 轮询刷新（无则 30s）                       | ✅     | SSE 通道 stream/task-center（api-conventions §5，S3 接入——登记勘误候选） |
| STUCK 展示：RUNNING 超 10 分钟无心跳任务标「疑似卡死」+重跑引导            | ✅     | 自动回收重派（S3，EXEC-002 登记）          |
| 定时任务 Tab：框架+空态（说明文案：随场景定时(S3)/计划定时(S4)/Swagger 同步(S6)接入） | ✅（空态） | 上述三个数据源                              |
| 删除任务记录                                                               | ❌     | 报告删除联动（RPT-002 承载，避免双口径）   |

### 1.3 前置依赖

EXEC-002 任务操作端点；ExecItem 聚合口径（API-003 冻结）。

### 1.4 对标基线核对

完全复刻：实时任务四能力（查看/详情/报告/重跑）。简化实现：三级范围→两级（单组织部署，系统级=全部项目）；实时通道轮询先行（SSE S3）；定时任务=框架空态（数据源均在后续迭代，避免假实现）。

## 2. 业务逻辑

- 范围过滤（rbac §5）：本项目 Tab=当前项目；全部项目 Tab=用户经项目成员/组织角色可见的项目集合（服务端 IN 过滤，防越权枚举）。
- 进度列：非终态任务取 ExecItem 聚合（通过数/总数，RUNNING 实时）；终态显示终局徽标。
- STUCK 判定：status=RUNNING 且 updatedAt<now-10min（心跳续写 updatedAt 于任务级心跳落库）。

## 3. UI/UX 设计（高保真 docs/design/SYS-006-task-center/）

- 左导航「任务中心」独立组（perm PROJECT_EXEC_TASK:READ）。
- 页面：范围 Tabs（本项目/全部项目）+ 次级 Tabs（实时任务/定时任务）；筛选条（类型下拉：调试/接口用例；状态下拉：进行中/成功/失败/已停止/疑似卡死；创建人；时间区间）；表格如 §1.2 列；RUNNING 行状态点呼吸动画。
- 定时任务 Tab：空态插画+文案+「了解定时任务」折叠说明（三个接入点列表）。
- 行操作按钮按状态显隐（fail-closed：权限不足禁用+Tooltip）。

## 4. 技术架构

- 数据模型（已建齐）：ExecTask(type/status/refType/refId/clientTaskId 关联重跑源?——重跑溯源存 payload.rerunOf，免新列)、ExecItem(status)。
- 端点：`GET /api/v1/projects/{pid}/exec-tasks`（本项目，query：type/status/creator/timeRange/page）——扩展既有 GET（S0 仅调试历史）；`GET /api/v1/exec-tasks`（全部项目，服务端范围过滤）；复用 EXEC-002 stop/rerun。
- zod：execTaskListQuerySchema。
- 权限点：PROJECT_EXEC_TASK:READ|UPDATE（API-003 入库；全部项目 Tab 额外要求任一项目成员身份——服务端求交）。
- 前端：`/tasks/page.tsx` + `TaskTable.tsx`；TanStack Query `refetchInterval` 动态（存在 RUNNING→3000ms，否则 30000ms）。
- 心跳续写：internal 心跳端点对 RUNNING 任务 `touch updatedAt`（STUCK 判定数据源）。

## 5. 测试用例

- SYS-006-T1（jmx 四类）：两级列表+筛选；401/403（无 EXEC_TASK:READ）；query 非法 422（时间区间倒序）；分页信封+排序。
- SYS-006-T2（spec 主链路）：批量执行 3 用例→任务中心本项目 Tab 出现 RUNNING（进度实时变化）→终态 FAILED（含 1 失败）→「重跑」→新任务「重跑自」溯源（UI+Console+接口）。
- SYS-006-T3（spec 范围二态）：全部项目 Tab 不出现无成员关系项目的任务（接口断言过滤）；定时任务 Tab 空态呈现。
- 单测：范围过滤（成员∪组织角色）、STUCK 判定边界、动态轮询间隔纯函数。
